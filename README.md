# dsh-work-diary

DSH Web GUI 的每日日记插件。侧边栏多一个「日记」图标，点开是主面板：按天汇总当天有活动的所有会话，生成一份中文 Markdown 日记；可每天定时自动生成，也可随时手动生成，用来做总结的模型可配置。

## 为什么做这个

AI 时代信息量太大，一天开十几个会话、跑几十个工具调用，到下班回头看，根本想不起今天到底干了什么。工作量遗忘得越来越快，但又没有精力每天手动记一笔。

所以就加了这么个工具：让 DSH 自己把当天的会话翻一遍，攒成一篇日记。不用真的去读全部内容，只要知道「大致今天做了什么事情」就够了。

## 做什么

- 按本地时区筛出某一天**有活动**的全部会话（默认当天，可切到昨天或任意日期）。
- 「有活动」的判据是 `sessionController.list()` 的 `updatedAt`（最近一次真人提问时间，取自持久化的投影缓存）并上最近 7 天创建的会话，不是会话创建时间——跨天继续干活的长会话不会被漏掉。
- 每个会话只取元数据（消息数、工具调用数、起止时间）和用户诉求样本，拼成摘要交给模型。诉求先滤一道噪声（整句客套、短追问、整段粘贴的代码、日志或表格），再取首尾各一条、各截 200 字；40 条以上的长会话额外补一条「主线」（滤完后最长的那条诉求，截 120 字）——这种会话只看首尾等于没看。
- 模型按固定节输出：今日概览 / 按项目列出今天做了哪些工作（精简档）/ 遗留与下一步（完整档）。
- 面板下方始终显示当天会话明细，点卡片直接跳到对应会话。

## 用法

1. 侧边栏点「日记」图标。
2. 顶部选日期（今天 / 昨天 / 日期框），点「生成总结」，正文流式出现。
3. 想改定时或模型：点右上角「设置」，内联展开设置区，改完点「保存设置」。

已经有总结的日期，按钮会变成「重新生成」——再点一次就是一次真实的模型调用，别顺手重复点。

## 预计花费

读会话不花 token：那部分是本地磁盘 I/O，走 `sessionController` 和 `sessionQuery`，完全不碰模型。**只有生成那一次调模型。**

按默认精简档、一天跑一次估算：

| 项 | token | 说明 |
| --- | --- | --- |
| 输入 | 约 1450 | digest 1856 字符（13 个会话实测，按中文约 1.5 字/token 折约 1240）+ 提示词模板约 200 |
| 输出 | 400–900 | 目标 600 字，`maxTokens` 硬顶 900 |
| 思考 | 约 100–300 | 已压到该模型支持的最低档位 |
| **合计** | **约 1950–2650 / 天** | 自动执行一天一次；手动生成则点一次算一次 |

参照量级：一次普通对话提问大约 1000–3000 token。也就是说这个插件一天的固定开销，约等于问模型一两个问题。

几点说明：

- 上表按 13 个会话实测：digest 取样改造前后分别是 1872 / 1856 字符，噪声过滤删掉的行与长会话新增的「主线」行几乎抵平，**这次改造基本不涨钱**（约 -11 token）。
- 会话越多、粘贴的大段内容越多，输入侧越贵——精简档的截断与噪声过滤就是为此设计的。
- 改成完整档（`verbosity: 'full'`）输入侧会明显上涨：同样 13 个会话实测 digest 约 3794 字符（约 2530 token），加上模板约 2730，输出硬顶 1600，合计约 4300 / 天。日常看概览用默认精简档就够。
- 如果只想手动看、不想每天固定花钱，设置里关掉「每天定时生成」即可，花费降到 0，只有你点「生成总结」时才发生。

## 省 token 的做法

目标是「大致了解今天做了什么」，所以默认走精简档，从取样到输出逐层压：

- **诉求取样先滤噪声**：会话的首条和末条经常不是「做了什么」，而是「继续」「好的谢谢」这类客套、短追问，或者整段粘进来的代码、表格。这些原样送去等于花 token 买噪声，所以先过滤再取样：
  - 整句只由客套词拼成（去掉标点后只剩「好的 / 谢谢 / 继续 / ok / thanks」这类），才算客套；
  - 短追问：疑问性开头（「所以 / 那 / 然后 / 是不是 / 有没有」）+ 疑问语气收尾 + 不足 20 字，三条同时成立才丢，避免误杀「帮我把并发降到 4？」这种真指令；
  - 整段代码：首词是 `const` / `function` / `select` / `import` 之类**并且**近处出现语句标点（或者多行带分号花括号），只看首词会把「delete the temp files」这种正常英文句子误判成代码；
  - 整段粘贴的日志 / 命令：长度 60 字以上而中文占比不足 25%。实测真实述求的中文占比都在 26% 以上，日志、报错栈、curl 命令在 1% 到 12%，两边分得很开。这条是必需的——「取最长诉求」的启发式专门爱挑粘贴物，10-26 实测三个 501 字段的会话，最长的一条全是 `email_analysis - INFO - 开始处理请求`、`SalesIntegrationError WARNING`、`curl --location --request POST` 这类，没有这条判据时主线行会被日志占掉；
  - 标题另有一套判据，只排代码与过长粘贴，短标题（「git 版本」）照常保留——否则摘要头会全退化成项目名，分不出会话。
- **取样与截断**：过滤后取首尾各若干条，逐条截断（`brief` 200 字 / `full` 500 字）。以前是先 `join` 再整体截断，`full` 档号称「首尾各两条、各 500 字」，实际是两条合吃 500 字；现在每条各吃一份额度。首尾有重叠时按多留的候选补位，不会白丢条数。
- **长会话补「主线」**：诉求 40 条以上的会话，首尾两眼看不到中间，额外送一条「主线」＝过滤后最长的那条诉求，截 120 字（`full` 400 字），排在「开头」和「结尾」之间。2026-10-26 实测的 254 / 165 / 119 / 49 条那四个会话，正是首尾取样完全瞎掉的那几个，这一行是专门补这个洞的；短会话不加，不花这份钱。
- **其他**：`brief` 档不送 cwd 长路径，时间与规模合并成一行；跨天会话的起止时间会两端都带日期（`10-23 17:46 - 10-26 17:35`），不再显示成看着倒挂的 `17:46-17:35`。
- **输出侧**：请求带 `maxTokens` 硬顶（`brief` 900 / `full` 1600）。提示词里写「不超过 600 字」模型经常不听（实测自动跑写了约 1100 字），只有请求字段能兜住；留一倍余量是免得把正文截断在半句。
- **思考档位**：自动取该模型支持的最低一档（`llm.resolveModelInfo` 的 `reasoning.efforts` 按从低到高排序，取第一个）。摘要不需要长思考，而思考 token 常常比正文还贵。模型不暴露档位就不传，让适配器用它自己的默认。

净效果：客套、短追问、粘贴的代码与日志不再进 digest（省），长会话多一条主线（花）。用 2026-10-26 的 13 个会话实测，改动前 digest 1872 字符、改动后 1856 字符，两边基本打平——省下来的正好够付新增的主线行。

## 配置

设置保存在 `[DSH_HOME]/work-diary/settings.json`（`DSH_HOME` 未设置时为 `~/.dsh`）。字段：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 是否每天定时自动生成 |
| `time` | `18:00` | 本地时间 HH:MM，到点自动跑一次 |
| `provider` | 空 | 总结模型的 provider；provider 与 model 都为空表示跟随默认模型 |
| `model` | 空 | 总结模型的 model |
| `language` | `zh` | 输出语言，`zh` 或 `en` |
| `verbosity` | `brief` | 详细程度：`brief` 精简（省 token）/ `full` 完整 |
| `maxSessions` | `40` | 单次总结最多纳入多少个会话，超出的在面板上提示数量 |

设置面板里可直接改开关、时间、provider / model、语言、详细程度；`maxSessions` 需要手改 `settings.json`（改完下次启动生效）。

生成结果按日期保存在 `[DSH_HOME]/work-diary/last-runs.json`，保留最近 30 份。打开面板时如果该日期已有结果，直接显示，不会重复生成。

自动执行：到点对当天跑一次（面板状态显示「自动」）；DSH 启动时若当天还没有结果、且当前时间已过设定时间，会立即补跑一次，Host 日志里能看到 `catch-up` 字样。

## 实现说明

- 读会话走 Host 服务 `sessionController`（拿当天有活动的会话清单）与 `sessionQuery`（拿标题、事件元数据、用户诉求正文），不直接读会话文件。
- 每个会话只读一次：`sessionQuery.readSession` 的 listEvents / readEvent / readSession 每次都全量加载会话日志，观测缓存只有 5 条 LRU，所以一次 `readSession` 同时拿 header、标题、计数、首尾诉求（「主线」候选是从同一份诉求列表里本地挑的，不额外读日志），比旧的「listEvents + readTitleSnapshots + 4×readEvent」快一倍以上。
- 候选会话取两路并集：`sessionController.list()` 里 `updatedAt` 命中当天的，加上最近 7 天创建的。`updatedAt` 取自持久化投影缓存、不是全覆盖，缓存没覆盖的会话会退回 `createdAt` 而被漏掉，第二路就是补这个漏；最后用 `readSession` 的真实事件时间终审，第二路纯追加，猜错只会多读几个会话，不会漏。
- 生成走 `llm.stream` 流式接口，走哪个模型由设置决定，空则跟随 `agentDefaultModel`。
- 模型输出的结束原因（`finishReason`）跟着结果一起落盘、并由 `poll` / `saved` 回传面板：撞上 `maxTokens` 的那次（值形如 `length` / `max_tokens`）会在正文下方标出来，避免把半句话当完整日记。落盘也带这个字段，所以重开面板、切回该日期时警告仍在。
- 同一天的并发收集会合并成一次；过去日期的结果不会再变、直接缓存复用，当天的只信 5 分钟，之后重读——足够盖住反复开关面板，又不会看到太旧的清单。面板 collect 与生成时的 collect 因此能共享同一次扫描。
- 面板打开先秒调 `saved`（只读落盘的 JSON，几毫秒）把已有总结显示出来，再后台收集会话列表，不用对着空面板干等；模型清单则等点开设置区才取，避免和收集抢 Host 时间。
- 内存里最多保留 8 份运行记录，同一日期重复点「生成总结」会复用正在跑的那一次。
- 单个会话读取失败只跳过该会话并记一行日志，不影响整次总结。

## 安装

本包是静态 cordis bundle，没有构建步骤：`lib/index.js` 是 Host 半边，`lib/client.js` 是 Client 半边，`cordis.patch.yml` 声明要挂载的行，`icon.svg` 是侧栏图标。

1. 把本目录放到任意位置（和其他插件放在一起即可）。
2. 用 DSH 插件管理器的「安装本地 bundle」把它装入当前 profile。这一步会写好 profile 的依赖项与 `dsh.profile.bundles` 挂载，**不需要手改 profile**。
3. 重启 DSH，侧边栏出现「日记」图标。

改完代码需要重启才生效：模块进程启动时加载，Node 的模块缓存会一直用到重启。
